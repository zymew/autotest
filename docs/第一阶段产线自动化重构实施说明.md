# 第一阶段产线自动化重构实施说明

## 本次重构的目标

这次实现把原来的沙盒主链路，从“识别机型、拉规格、回传最终结果”升级为更贴近真实产线的最小骨架：

- 控制机管理任务，而不是只收一个 JSON
- DUT/Agent 以 `SN` 为主键注册上线
- 测试过程按测试项推进并实时上报
- 结果目录可沉淀为后续电子档案
- 看板与 `SN` 追溯先用最小 HTML/JSON 视图落地

## 当前已落地的能力

### 控制机

- `POST /api/tasks/register`
  - 为 DUT 分配或复用任务
  - 返回 `task_id`、`model_code`、`test_plan`
- `POST /api/events`
  - 接收 `lifecycle / telemetry / event / result`
- `GET /dashboard`
  - 最小工位看板
- `GET /trace/<sn>`
  - 最小 `SN` 追溯页
- `GET /api/tasks`、`GET /api/tasks/<task_id>`
  - 查询任务和单任务事件流

### Agent

- 启动后自动注册任务
- 自动执行：
  - `inventory_check`
  - `lan_check`
  - `serial_loopback_check`
  - `burnin_check`
- 对 `usb_check / display_check / io_check` 先输出占位 `SKIP`
- BurnIn 期间按周期上报遥测心跳

## 当前配置模型

主配置文件仍为：

- [controller/specs/model_specs.json](/C:/Users/19306/Documents/自动测试/controller/specs/model_specs.json)

但它的角色已经从“复杂规格库”收敛为“轻量测试计划配置”，重点包含：

- CPU 关键字规则
- 内存容量与品牌要求
- 硬盘品牌与容量要求
- LAN 判定阈值
- 串口回环参数
- BurnIn 配置
- 测试项启停开关

## 与最终愿景之间的关系

这次实现是产线自动化骨架，不是最终完整方案。下面这些点已经预留了扩展口，但还没在仓库里完整落地：

- 真正的 MQTT broker 接入
- Grafana / 时序库存储
- 多工位任务编排
- USB 夹具自动化
- 显示口自动化
- IO 内部针脚治具化测试
- 测后正式系统部署闭环

因此，当前版本的价值主要在于：

1. 先把 `SN + 任务 + 事件 + 遥测 + 追溯` 这条主数据链立住
2. 让后续接入 MQTT/Grafana 时不用推倒 agent 和控制机数据模型
3. 让原本只会“跑完写一个结果”的 agent，具备产线化扩展方向
