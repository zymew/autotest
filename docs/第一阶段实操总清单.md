## 一、第一阶段目标

第一阶段现在已经收敛为“先把产线自动化骨架立住”，不是直接冲完整产线。

本阶段主目标：

- 让控制机不再只是收一个最终结果 JSON，而是能管理任务、接收事件、保存追溯数据
- 让 WinPE Agent 不再只是一次性脚本，而是能按测试项执行并持续回传状态
- 先跑通最核心的自动测试主线：
  - `CPU`
  - `内存`
  - `硬盘`
  - `LAN`
  - `串口`
  - `BurnIn`
- 先不做：
  - `显示口`
  - `IO`
  - `USB 真正自动化`
  - `MQTT/Grafana 真接入`
  - `正式系统群播/无痕闭环`

一句话总结：

- 第一阶段先把“任务 + 测试项 + 结果 + 追溯”主骨架搭好

## 四、你现在需要做什么

下面这些是当前最需要你配合完成的事情。

### A. 先完成 Day2 的“现场主链路确认”

你需要做的不是先改代码，而是先把环境和素材补齐：

1. 确认 Ubuntu 控制机服务能正常启动
2. 把最新 `controller` 目录同步到控制机
3. 准备可启动的 WinPE
4. 确认 WinPE 里带上新的 `scripts`
5. 确认 PXE 文件就位
6. 用 1 台 DUT 做首轮启动验证

### B. 准备一台真实 DUT 的最小配置

你需要准备：

- 真实 `SN`
- CPU 实际型号
- 内存实际容量和品牌
- 硬盘实际容量和品牌
- 实际 LAN 使用方式
- 实际串口数量
- BurnIn 对应配置文件名

目的不是做复杂机型库，而是先把 1 台真机跑通。

### C. 现场判断串口测试怎么落

当前代码已经预留了串口回环逻辑，但你现场还需要确认：

- 这台 DUT 现场到底测几个串口
- 232 和 485 是不是同一轮都测
- 当前回路头接法是否支持自动回环
- WinPE 环境里是否能用 `pyserial`

这一步不要求你现在就全解决，但要先搞清楚现实接线条件。
